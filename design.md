# Architecture
## Goals and decisions
Use Node.js 22, Express 5, Vercel AI SDK, an Anthropic model selected by configuration, and Tavily Search. The model has exactly one registered tool named `webSearch`. Memory, validation, caching, clock access, and routing are application services, never model tools. Configure a tool-capable model through `Model`; provider choice is isolated to the server composition root.
## System design and data flow
User -> Express API -> Memory Manager -> LLM Router -> Search Tool -> Streaming Response.
Express authenticates requests, validates input, acquires the session lease, records the server receipt time, and starts SSE. The memory manager supplies the complete retained transcript with trusted timestamps. The executor routes `grounded` requests through a required search step and `auto` requests through optional search. One tool invocation executes one to three independent queries concurrently. The next model step synthesizes with tools disabled. Text deltas flow immediately to the client; sources and terminal status are separate SSE events. The memory manager records the completed or interrupted assistant turn before emitting `done`.
## Contracts and module boundaries
`src/memory.js`: `mm()` returns the bounded session store; `cr()` creates a session; `ac(id, text)` acquires a turn; `cm(session, text, status)` commits its outcome; `gc()` expires idle sessions. Session identifiers are server-generated UUIDs. Descriptive JSON fields coexist with short code identifiers to satisfy the naming constraint without obscuring the external protocol.
`src/search.js`: `ws(key, session, signal, emit, fetch)` constructs the sole tool. Its validated input contains `queries` and `fresh`. Results contain original query, retrieval time, title, URL, bounded excerpt, and publication time when supplied. API failures return explicit unavailable evidence instead of invented results. Dependency injection permits offline testing.
`src/agent.js`: `ax(session, model, tool, signal, emit)` executes at most two model steps. It stores partial text and status even when streaming, cancellation, provider errors, or output limits terminate a turn. The SDK and provider retain their required property names; every authored variable, parameter, import binding, and function identifier uses one or two characters and excludes `l`.
`src/server.js`: `sv(config, model, fetch)` composes authentication, validation, session lifecycle, admission limits, backpressure, cancellation, logging, and graceful shutdown. Configuration is validated before listening.
## Temporal memory
Each session stores `sessionId`, `timestamp`, `messageHistory`, a sequence counter, a lease flag, and a private evidence cache. Each message stores role, content, UTC ISO 8601 timestamp with millisecond precision, sequence, and completion status. User timestamps represent server acceptance, not an unverifiable client send time. Assistant timestamps record completion or interruption. Sequence numbers disambiguate equal timestamps. Accurate wall-clock time depends on the host clock being synchronized.
Each request supplies a validated IANA time zone, defaulting to UTC. The system prompt carries current UTC time, the session time zone, and an authoritative message-index-to-timestamp table. Message bodies remain in their original user or assistant roles. Relative dates in historical messages are interpreted against that message's timestamp and time zone, not today's date. User content and search text cannot override trusted clock metadata. Incomplete prior output is marked as such and must not be treated as established fact.
Retain all accepted messages for 30 minutes of inactivity, bounded by 1,000 sessions, 64 messages per session, and a 40,000-byte admission threshold. Do not silently summarize or discard old turns. Reserve additional room for the new input and a bounded answer; once full, return 413 and require a new session. Prompt size is conservatively bounded by UTF-8 bytes rather than an inaccurate characters-to-tokens ratio; choose a model supporting at least a 128K-token context. In-memory storage disappears on restart. Multiple workers require sticky routing or a replacement shared memory adapter.
## Latency and accuracy
Stream SSE text deltas as soon as generated. Disable proxy buffering, send keep-alive headers, and honor Node response backpressure. Clients consume POST responses through fetch streaming; native EventSource cannot POST. The response includes a request ID, session ID, sources, and a terminal `done` or `error`; a disconnected stream without `done` is not a completed answer.
Run up to three Tavily requests in parallel inside the single tool, with individual eight-second deadlines and a 45-second request deadline. Bound each request to five results and each excerpt to approximately 2,000 UTF-8 bytes. Cap URLs, titles, and publication dates as well. Use basic search for latency, with no generated search answer or raw page download. A maximum of one tool invocation prevents runaway search costs. Global admission allows 32 active turns. Model retries are disabled so latency and costs stay predictable; callers receive a structured failure.
Implemented evidence caching is exact-query, per-session, capped at 64 entries, and expires after 60 seconds. `fresh` defaults to true, bypassing cached evidence for current facts. Cache retrieval timestamps remain unchanged. Failed searches are never cached. Separate sessions never share queries or answers.
Semantic answer caching is deliberately disabled in this baseline. An optional future implementation should embed normalized intent, prior conversation state, time zone, absolute date interpretation, model and prompt version, and evidence revision; partition by session or authenticated owner, enforce short TTLs, and validate entities, numbers, and temporal qualifiers after similarity matching. Similarity alone is unsafe for questions differing by dates or negation. Benchmark whether embedding and verification cost actually improves p95 latency before enabling it. This is an internal optimization, not an additional agent tool.
Grounded mode forces retrieval before the final synthesis; auto mode avoids retrieval for conversation-only tasks. The prompt requires citations only to returned URLs, separation of evidence and inference, explicit source disagreement, and admission of insufficient evidence. Returned web text is untrusted data and cannot instruct the agent. Publication dates may be absent; retrieval time is not publication time. Excerpts can omit important context, and streaming cannot guarantee factual entailment or retract an already emitted claim. Strict prepublication verification would require buffering and an additional internal verification pass, trading latency for assurance.
## Reliability and security
Require an application bearer key on every endpoint. Session UUIDs act as additional capability tokens; this challenge implementation assumes a single trusted application. A public multi-user deployment must add real identity and bind session ownership to it. Reject unknown and expired sessions rather than creating them implicitly. Return 409 for overlapping turns, 503 for capacity, 413 for oversized input/history, and 400 for invalid payloads. Disable Express branding, limit JSON bodies, and never log prompts, credentials, or search excerpts.
Abort the model and searches on disconnect or deadline. Always release leases, including on exceptions. Retain partial assistant text with an interrupted status; errors never masquerade as successful answers. Sweep expired idle sessions periodically and never evict active sessions. Search errors are exposed to the model as unavailable evidence. Server errors expose safe codes and a request ID while server logs record timing and error class.
## Evaluation
Measure request acceptance to first text token separately from total response latency, search duration, cache hit rate, and successful completion rate. Benchmark cold and warm requests at multiple concurrency levels and report p50/p95/p99. Evaluate citation support, current-fact freshness, insufficient-evidence abstention, date resolution across time zones and midnight, multi-turn recall, source prompt injection, and conflicting evidence. Offline tests cover session locking, isolation, timestamps, expiry, capacity, cache freshness, partial search failure, streaming errors, and the exactly-one-tool contract. Live factual and latency evaluation requires provider credentials and a representative challenge dataset; no latency or accuracy numbers are claimed without measurement.
